Consta Data Model

Everything hangs off case_file. The schema is organized around one question: what happens when a lawyer deletes a case file? Content derived from the PDF goes with it. What the lawyer was billed for stays.

Case file lifecycle

uploading→ queued→ processing→ mapping→ ready

failed can follow any step after upload, and deleting marks a case file on its way out. During processing, one ingestion_range row per 100 pages tracks each parallel task, and pages_done counts finished pages. mapping writes peca and fact.

Inside question.answer

The column is untyped jsonb. The shape it is meant to hold is the Statement type in packages/core/src/answering/index.ts. Citations copy the page number and folha by value.

// Statement[]: a statement always has at least one citation (ADR-0003)
[{
  text: string,
  citations: [{
    page:  number,          ⇢ page.number
    folha: string | null,   // copied from page.folha
    quote: string,
    boxes: Box[]            // {x0, y0, x1, y1} as fractions of the page
  }, ...]
}]

Gaps and planned fixes

The diagram shows the schema as it is today. Each gap below is now an acceptance criterion on the ticket that builds that part.

  1. designDeletion is built into the foreign keys.

    Cascade, set null and "no FK" are each used on purpose. Content goes with the case file; usage and quota charges stay. The PDF in S3 is removed separately by CaseFiles.remove.

  2. highQuota charging can be oversubscribed, and failed ingestions used up quota.

    Checking with pagesLeft and then calling chargePages lets two concurrent uploads both fit. Fix: chargePages locks the lawyer's lawyer_plan row, checks and charges in one transaction, and a unique index on quota_charge.case_file_id makes it idempotent (ticket 04). Ingestion.fail gives the pages back (ticket 05).

  3. mediumpage has no primary key, and nothing has a foreign key to it.

    Fix: primary key (case_file_id, number); passage references it with cascade, so a retried range deletes its pages and the passages follow (ticket 05). fact references it too, and peca and ingestion_range check first_page <= last_page (tickets 05, 09). Citations inside the answer JSON stay unconstrained, which is safe because pages don't change after ready.

  4. mediumquestion.scope mixes scope and quick action.

    CONTEXT.md treats them as two concepts. Fix: scope becomes an enum of whole-file and peca, a nullable quick_action enum is added, a check ties scope = 'peca' to a non-null peca_id, and peca_id moves to cascade so the check can't be broken (tickets 07, 10, 11).

  5. lowlawyer_id has no foreign key yet.

    Ticket 02 brings the Better Auth tables into the migrations and creates the Trial plan row on first sign-in. It now also adds foreign keys from lawyer_plan, case_file and question. usage_event and quota_charge stay unconstrained so billing records outlive the account.

  6. lowUntyped JSON.

    question.answer gets $type<Statement[]> (ticket 07), and question.feedback gets a type whose "wrong page" flag names a citation by statement and citation index (ticket 14). ingestion_range.status and usage_event.unit stay text enums checked only by the app; that's left as is.
